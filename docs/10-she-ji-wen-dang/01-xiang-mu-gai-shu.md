# 1. 项目概述

## 1.1 项目背景与建设目标

结合需求梳理与旧版文化惠票务系统在用户体验、功能完善等方面的不足，产研团队作出新版文化惠平台的系统设计方案。本次系统建设旨在开发一套功能完善、安全可靠、智能化的文化惠票务系统。

2026年整体升级目标：围绕"大数据分析、用户精准画像、AI智能服务、全区演艺场馆与剧目资源整合"四大方向，实现平台从基础服务向智能化、精细化、一体化升级，提升运营决策能力、用户服务能力和行业影响力，最终达成"一站式文化消费入口+产业服务枢纽"的建设目标。

## 1.2 建设内容

以下内容按 repo 已实现写（main `161a8c4`，2026-11-16 核对；以代码为准，
不以本文档为准）。数字均为代码中数出：数据库 45 张表
（`server/schema.mjs` 的 `CREATE TABLE` 数）；资源 62 个、分类 10 个
（`server/demo-data.mjs` 22 个 + `server/catalog-content.mjs` 40 个）；
后端路由文件 41 个（`server/routes/`），接口约 80 个（去重后的
`/api/` 路径数）；管理端 8 个视图；H5 文案 483 条/语言（中/越/英，
泰/马/印尼 82 条核心集），小程序 270 条/语言（中/越/英）。

已建功能（按子系统）：

- **资源与目录**：62 个广西演艺资源（演出剧目、场馆、艺人、设备、
  版权、非遗、文创、数字、旅游、服务），分类/城市/关键词/价格/
  评分检索，详情、收藏（须登录）、浏览/点击/搜索埋点。
- **预订与场次**：按日期预订（租赁类按日、服务类按需、文创类现货）；
  演出（场次）按场次售票：演出须审核通过后建场次、票种、取票点、
  座位；非演出资源也可直接建场次（无须演出审核），顾客下单须选
  场次与票种。订单金额、预订日期均由服务端计算。
- **订单与售后**：pending → confirmed → paid → completed，取消/
  退款（含部分退款）、交易保障（托管/释放/冻结）、票务核验/
  打印/批量核销、出票（票码）。
- **会员与营销**：会员等级与折扣、优惠券（叠加顺序：底价 → 会员
  折扣 → 券）、限时抢购（每场次同时仅一场）、文惠卡储值、
  自动赠券、用户画像（基础属性/消费能力/观演偏好/行为偏好/
  渠道来源）与推荐。
- **需求与互动**：需求发布/审核/匹配、评价（须审核）/站内信、
  知识图谱关联、行程建议。
- **多店铺**：总店 + 子店、店铺主题（横幅/主色/版块顺序）、
  店铺管理员仅见本店资源；平台管理员见全部。
- **智能服务**：规则客服（H5 浮动聊天 + 小程序助手）；H5 聊天
  经同源代理调用 Lam 的试用 agent（真实 DeepSeek + RAG，
  2026-11-11 已验证），正式 AI 中台未建；语音购票（文字输入
  解析为草稿订单，人工确认后付款）；AI 文案生成用真实生成
  （不可用时回退本地模板）。
- **管理端**：独立 admin web，8 个视图（总览/订单/用户/资源/
  需求/趋势统计/经营分析/预警中心），另有店铺、演出、场馆、
  票种、取票点、座位模板、会员、券、抢购、短信、版权、文惠卡、
  账本、埋点、审计等管理面；操作留痕（审计日志）。
- **微信小程序**：目录、详情（场次/票种/座位/取票点）、订单、
  收藏、助手，与 H5 同一套后端。
- **账号与安全**：注册/登录（scrypt）、邮箱/手机 OTP（邮箱 OTP
  已接真实发送；手机 OTP 为演示码）、三角色权限（见 1.3）。
- **部署**：Node 后端 + React 前端 + PostgreSQL + Redis（缓存，
  故障时直连数据库）；Docker 镜像 + compose（一键起全部服务）；
  生产在 Vercel + Neon。

**模拟能力必须标注**：支付、AI、区块链、VR、渠道同步是模拟，
界面写明（模拟支付、模拟托管中等），不得写成真实/已上线。
需求表 82 行（`upload-2.xlsx`）是后续路线图，不在本节已建范围
内重复列出。

## 1.3 用户与角色

以下按 repo 已实现写（`server/lib/roles.mjs` 与 `server/seed.mjs`，
main `161a8c4`，2026-11-16 核对）。三类账号（`users.role`，
无 CHECK 约束，`root` 只是第三种取值）：

| 角色 | 权限（服务端强制执行，403；不只在界面限制） |
|---|---|
| `root` | 默认管理员账号（id 1，最高）。任何人（含自己）都不能在管理端编辑/停用/降级 root；只有 root 能授予/收回 `admin` 角色（`PATCH /api/admin/users/:id/role`）；只有 root 能停用另一位管理员（FINDING-1，Lam 2026-11-15 定）。 |
| `admin` | 管理端全部权限，但：不能碰 root 账号，不能授予/收回角色，不能改另一位管理员的状态。店铺管理员（`shop_id` 已设）只见、只改本店资源；平台管理员（`shop_id` 为空）见、改全部店铺。 |
| `user` | 注册/登录的普通顾客：浏览、购票、收藏、发需求、评价、站内信、查看自己的票；无管理端权限（一切管理接口 403）。 |

未登录访客只能浏览；收藏须先登录（未登录点收藏只提示登录，
不存本地）。每次角色变更都写审计日志。

演示账号 `demo` / `admin`（公开演示凭证，见小组文件 08）：
`demo` 为普通顾客，`admin` 为默认管理员（id 1，`root`）。
