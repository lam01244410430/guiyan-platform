# 安全与稳定性

> 正式安全专章待小组补充。本章只写"现状是什么 + 缺口是什么"，不编造安全规范。

## 现状（main `90171d3`，已验证）

- **账号与密码：** scrypt 加盐哈希，绝不明文。演示账号密码只来自环境变量
  （`DEMO_PASSWORD` / `ADMIN_PASSWORD`），不进 repo。种子用户共用公开演示密码
  `guiyan2026`（与 demo123 同类，demo-only，已在文档中注明）。
- **会话：** 登录返回 token（7 天），存在 `sessionStorage`（客户站 `guiyan-token` /
  `guiyan-user`，管理站另有自己的键）；登出清除。
- **权限：** 管理端接口只认 `role=admin`，匿名与非 admin 一律 **403**（不是 401）；
  POST 到管理端返回 404。收藏写操作要求登录，匿名 POST 返回 401。
- **注入与遍历：** 全部写操作走事务与参数化查询；静态文件服务有反斜杠/`..`/符号链接
  遍历防护。
- **金额：** 服务端自己算订单金额，客户端传来的金额忽略；钱一律整数分。
- **缓存故障隔离：** Redis 坏了只读 Postgres（fail-open），绝不影响请求；会话仍在 Postgres。
- **审计：** 注册、关键操作写 `audit_logs`；管理端可读最近 60 条审计日志
  （`GET /api/admin/audit-logs`，后端已实现，UI 在阶段 5）。
